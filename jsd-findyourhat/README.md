# 🎩 Find Your Hat Game

เกม text-based ที่ผู้เล่นต้องเดินในสนามเพื่อค้นหาหมวก โดยหลีกเลี่ยงหลุมและไม่เดินออกนอกสนาม

## 🎮 วิธีเล่น

รันโปรแกรมด้วย `node index.js` แล้วพิมพ์ทิศทาง:

- `u` = ขึ้น
- `d` = ลง
- `l` = ซ้าย
- `r` = ขวา

### สัญลักษณ์

- 🎩 = หมวก (เป้าหมาย)
- 💀 = หลุม (อันตราย)
- 🟩 = พื้นสนาม
- 😎 = ตัวผู้เล่น

## 🏆 เงื่อนไขการเล่น

- ✅ **ชนะ**: เดินไปถึงหมวก
- ❌ **แพ้**: ตกหลุม หรือเดินออกนอกสนาม

## 📦 การติดตั้ง

```bash
npm install
node index.js
```

## 🧠 Thinking Process

### ขั้นตอนการคิดวิเคราะห์

**1. วิเคราะห์โจทย์**

- Input: ทิศทางที่ผู้เล่นเลือก (u/d/l/r)
- Output: สนามที่อัพเดทแล้ว + ข้อความแจ้งผล
- Data Structure: 2D Array สำหรับเก็บสนาม

**2. แบ่งโค้ดออกเป็น 3 ส่วนตามหน้าที่ (Separation of Concerns)**

- `generateField()` — สร้างสนามแบบสุ่ม
- `Field` class — จัดการ state และพฤติกรรม
- `playGame()` — ควบคุม game loop

**3. ออกแบบ Algorithm สุ่มสนาม**

```
1. สร้างสนามเปล่า + สุ่มหลุมตามเปอร์เซ็นต์
2. สุ่มตำแหน่งผู้เล่น (do-while กันทับหลุม)
3. สุ่มตำแหน่งหมวก (do-while กันทับผู้เล่นและหลุม)
```

**4. ออกแบบ Game Loop**

```
while (status === 'playing'):
  - แสดงสนาม
  - รับ input จากผู้ใช้
  - ขยับตำแหน่งผู้เล่น
  - ตรวจสถานะเกม
```

---

### เหตุผลการเลือก Design Pattern

**1. Class-based Design (Encapsulation)**
รวมข้อมูล (field, playerRow, playerCol) และพฤติกรรม (move, print, check) ไว้ใน Class เดียว เพื่อป้องกันการแก้ไขข้อมูลจากภายนอกโดยไม่ตั้งใจ

**2. State Machine Pattern**
ใช้ตัวแปร `status` เก็บสถานะเกม 3 แบบ: `'playing'`, `'win'`, `'lose'` แทนการใช้ boolean หลายตัว ลดโอกาสเกิด bug

**3. Factory Function**
`generateField()` เป็นโรงงานผลิตสนาม รับ parameter ได้หลายค่า (ขนาด, % หลุม) ปรับความยากได้

**4. Guard Clauses (Early Return)**
ใน `checkStatus()` เช็คกรณีออกนอกขอบเขตก่อนเสมอ ป้องกัน error จากการ access array index ที่ไม่มีอยู่

**5. Constants Over Magic Values**
ตั้งชื่อสัญลักษณ์เป็น const (hat, hole, fieldCharacter, pathCharacter) ถ้าอยากเปลี่ยนสัญลักษณ์ แก้ที่เดียวจบ

### การตัดสินใจสำคัญ

**Q: ทำไมใช้ do-while ในการสุ่มตำแหน่ง?**
A: ต้องสุ่มค่าก่อนถึงจะมีค่าให้เช็คได้ว่าชนกับสิ่งที่มีอยู่แล้วไหม ถ้าใช้ while ปกติ ตัวแปรจะเป็น undefined ตอนเช็คครั้งแรก ทำให้เกิด error

**Q: ทำไมต้องเช็คออกนอกสนามก่อนเช็คหลุม?**
A: ถ้า index เป็นลบหรือเกินขนาด array การ access field[-1][5] จะทำให้โปรแกรมพัง ต้องเช็คขอบเขตก่อนเสมอ

**Q: ทำไม moveUp ต้อง -1 ไม่ใช่ +1?**
A: ระบบพิกัดของ 2D array กลับด้านกับกราฟคณิตศาสตร์ แถวที่ 0 = บนสุด ดังนั้นเดินขึ้น = row ลดลง

**Q: ทำไมใช้ switch แทน if-else?**
A: กรณีนี้มี 4 ค่าที่เป็นไปได้ (u/d/l/r) switch อ่านง่ายกว่าและเพิ่ม case ใหม่ได้ง่าย

**Q: ทำไมใช้ continue ในกรณี Invalid input?**
A: ถ้าผู้ใช้พิมพ์ผิด ไม่ควรนับว่าเดินแล้ว continue จะกลับไปรับ input ใหม่ทันที
